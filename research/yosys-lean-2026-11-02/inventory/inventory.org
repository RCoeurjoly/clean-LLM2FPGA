* Every production backend

Each entry names actual commands, records the format, and states semantics and restrictions. These are source-derived limits, not a promise that any arbitrary design exports.

** =write_rtlil= — RTLIL text

Category: internal structural IR.

Serializes Yosys internal design objects, including processes, memories, cells, hierarchy, attributes and X/Z constants; consumers still need RTLIL cell semantics.

No requirement to lower processes or memories. Main has Twine identity/replayable printing changes since v0.70; pin version and dialect.

Variants/options: -selected; -sort; main: -readable loses Twine identity/replayability; main: -small omits name comments.

Evidence: [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/rtlil/rtlil_backend.cc#L513][registration]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/rtlil/rtlil_backend.cc#L514][help]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/rtlil/rtlil_backend.cc#L384][source detail]].

** =write_json= — Yosys JSON netlist

Category: structural netlist.

Hierarchy, cells, parameters, attributes, ports, memories and bit connections; optional AIG models for supported cell types.

Processes are explicitly rejected: run proc. A syntactically present cell instance is not a definition of that cell's behavior. Memory/cell semantics need an interpreter.

Variants/options: -aig; -compat-int; -selected; -noscopeinfo; json pass exports selected objects.

Evidence: [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/json/json.cc#L339][registration]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/json/json.cc#L340][help]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/json/json.cc#L154][source detail]].

** =write_verilog= — Verilog; SystemVerilog output variant

Category: HDL netlist.

Netlist with expressions/always blocks for recognized internal cells and instances for external cells; hierarchy and memories can be emitted.

Help requires proc: RTLIL processes cannot always be mapped directly and trigger a warning. Unmapped/library instances still require external definitions. -sv emits constructs such as always_comb, not a distinct backend.

Variants/options: -sv; -noexpr retains internal cells; -blackboxes; -extmem emits readmemh .mem initialization sidecars.

** =write_aiger= — AIGER binary; ASCII AAG

Category: Boolean transition system.

Flattened AND/inverter graph with simple FF state; asserts become bad-state properties and assumes invariant constraints. Initstate/nondeterministic formal cells have special handling.

Requires flattened and gate-lowered design; no unprocessed memories/processes. Supported FFs include $_FF_ and $_DFF_[NP]_; arbitrary clocks/resets/enables must be normalized before interpreting an AIGER transition as a clocked hardware step. Unsupported cell kinds error. -ywmap currently requires -zinit.

Variants/options: -ascii; -zinit; -miter; -symbols; -map/-vmap port/latch maps; -ywmap JSON witness map.

Evidence: [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/aiger/aiger.cc#L893][registration]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/aiger/aiger.cc#L894][help]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/aiger/aiger.cc#L234][source detail]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/aiger/aiger.cc#L1021][source detail]].

** =write_aiger2= — AIGER binary

Category: combinational Boolean model.

Experimental newer writer directly ingests a larger supported subset of combinational coarse cells/gates and can traverse hierarchy with -flatten.

Not a drop-in sequential replacement for write_aiger: known_ops is combinational, no FF/memory operations. Unknown/blackbox cells fail; -flatten respects keep_hierarchy. Source has TODOs for inout, undriven and zero-width cases. Help generates its unsupported-cell list dynamically; literal extraction retains %s and raw C++.

Variants/options: -strash; -flatten.

** =write_smt2= — SMT-LIBv2

Category: formal transition system.

Per-module state sort, hierarchy relation, initial predicate, transition relation and assertion/assumption/cover predicates; BitVec arithmetic and ArraysEx memories by default.

Lower processes. Unmap sync reset/enables with dffunmap; async FFs need async2sync; dffunmap or clk2fflogic, and latches need clk2fflogic. Read-port registers must not be merged into memories (memory -nordff / memory_nordff). -nobv implies -nomem, -stbv disables array memories. Unknown cells fail unless explicitly supplied as SMT blackboxes; $live/$fair/$equiv are rejected. A proof driver must assert hierarchy/init/transition predicates correctly; clock normalization matters for multiple clocks.

Variants/options: -stbv; -stdt; -nobv; -nomem; -wires; -tpl; -solver-option.

Evidence: [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/smt2/smt2.cc#L1605][registration]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/smt2/smt2.cc#L1606][help]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/smt2/smt2.cc#L930][source detail]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/smt2/smt2.cc#L1697][source detail]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/smt2/smt2.cc#L1108][source detail]].

** =write_btor= — BTOR2

Category: formal transition system.

Bit-vector/array state, init/next transitions, bad properties and constraints. Despite command/help spelling BTOR, emitted sort/state/next syntax is BTOR2.

One top module; flatten hierarchy/resolve unknown cells. Normalize FF types as with SMT2 (dffunmap, async2sync or clk2fflogic); no synchronous memory reads (memory_nordff), no mixed sync/async memory write ports. Explicit error paths for unsupported cells. A hardware proof still requires an agreed clock-step model.

Variants/options: -s single bad property; -c covers instead of asserts; -i auxiliary info; -ywmap JSON witness map; -x symbols.

Evidence: [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/btor/btor.cc#L1590][registration]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/btor/btor.cc#L1591][help]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/btor/btor.cc#L806][source detail]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/btor/btor.cc#L965][source detail]].

** =write_cxxrtl= — C++ CXXRTL

Category: simulation code.

Executable RTL simulation code and optional header, with sequential state, memories, hierarchy, blackbox interfaces and explicit eval/commit stepping.

Requires driver clock/port interaction and race-free scheduling. Supports processes (normally lowers them unless -noproc); rejects unknown cells, unmarked external blackboxes, multi-driver wires and global-clock processes. C++ simulation model is not a Lean proof artifact.

Variants/options: -header; -noflatten; -noproc; optimization/debug levels; CXXRTL C API and VCD runtime are companion interfaces.

** =write_functional_cxx= — C++ Functional IR

Category: functional simulation code.

Per-selected-module pure evaluation/state functions and initial state using functional C++ runtime; separate from CXXRTL.

Shared Functional IR requires normalized global-clock FFs (FfData.has_gclk), not ordinary clocked FFs; source recommends async2sync or clk2fflogic. Collect memories with memory_collect; write ports must be asynchronous and read ports unclocked (memory_nordff). Memories without read ports are rejected. Undriven/multiply-driven nets, combinational loops, unknown cell kinds and $check are rejected; $check requires chformal -lower. Flatten/resolve hierarchy and lower processes before treating each selected module as a standalone function. X collision values are treated as don't cares. Command help is TODO; use source constraints rather than inferring maturity.

Evidence: [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/functional/cxx.cc#L243][registration]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/functional/cxx.cc#L245][help]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/kernel/functional.cc#L559][source detail]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/kernel/functional.cc#L610][source detail]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/kernel/functional.cc#L644][source detail]].

Collect memories with memory_collect; write ports must be asynchronous and read ports unclocked (memory_nordff). Memories without read ports are rejected. Undriven/multiply-driven nets, combinational loops, unknown cell kinds and $check are rejected; $check requires chformal -lower. Flatten/resolve hierarchy and lower processes before treating each selected module as a standalone function. X collision values are treated as don't cares.

Variants/options: -provides; -assoc-list-helpers.

Evidence: [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/functional/smtlib_rosette.cc#L324][registration]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/backends/functional/smtlib_rosette.cc#L326][help]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/kernel/functional.cc#L559][source detail]], [[https://github.com/YosysHQ/yosys/blob/63eecf3ddca2f143750f11e37ebd18ecb16b51c7/kernel/functional.cc#L610][source detail]].

* Limits, naming traps, and evidence artifacts

There is no registered built-in =write_lean=, =write_lean4=, =write_vhdl=, =write_btor2=, =write_simplecxx= or =write_sdc= in these snapshots. The real commands are =write_btor= (BTOR2), =write_simplec= (C), =write_cxxrtl= (C++), and =write_functional_cxx= (another C++ schema). Verific's optional VHDL pretty-printer is explicitly distinguished above.

- Finite source census, not every arbitrary file emitted by plugins, the shell/Tcl/Python APIs, ABC, Graphviz, OpenSTA or linked proprietary libraries.
- Auxiliary output survey includes explicit file options, reports, mapping sidecars, visualizations, solver traces and bundled witness tools; log text/debug AST dumps are not each counted as distinct whole-design interchange languages.
- Full raw C++ help bodies and literal help strings are retained in source-registry-*.json. Dynamic help expansion (notably aiger2 supported-cell exclusions) was inspected in source, not executed; %s placeholders are not actual runtime command output.
- Model generation is not by itself a proof of the exporter or a Lean-checked equivalence certificate; input domain, cell library, X/Z treatment, clock model and preprocessing must be fixed separately.
