#+startup: overview

* Scope and result

The full frozen quantized =model.pt2= is rejected by TorchLean's actual
Lean-generated capture adapter at =aten.embedding.default=. This run
builds the pinned upstream Lean modules and evaluates
=Export.PyTorch.TorchExport.script= in Lean; it does not reconstruct the
adapter from string literals. No operator rules have been changed.

The adapter is byte-for-byte identical to the earlier reconstruction:
SHA256 =0b8ca3cc8d882a92de05ed1dc750ecbd6ef46d2497821aee3039aba1074d4565=.
See [[file:adapter-provenance.json][adapter provenance]], [[file:03-emit-adapter.log][actual Lean generation]], and
[[file:capture-report.json][capture results]]. The actual [[file:artifacts/capture_adapter.py][Lean-emitted adapter]] is retained too.
The full model stops before producing graph JSON;
it has not been imported into a Lean program.

Two small supported saved exports pass the complete path: addition and
a Linear layer with directly available frozen weights. Lean accepts
their typed graphs and exact-word payloads, evaluates them using
TorchLean/FloatLib, and matches all *seven Float32 output words* against
PyTorch (four for addition, three for Linear). The addition case includes
negative zero. See [[file:result.json][final result]], [[file:06-add-check.log][addition check]], and [[file:07-linear-check.log][Linear check]].

Both examples take about 10.7 seconds per invocation and about 3.83 GiB
peak RSS, including loading the Lean libraries. These tiny-example
measurements do not determine whole-model import or execution memory.

| Saved-export case | Actual adapter result |
|-------------------+-----------------------|

claim that adding embedding alone would import the complete model.
The earlier full-graph inventory found 315 rejected call sites across
18 operator identities; that inventory's limitations remain documented
in [[file:../model-probe/README.org][the original probe]].

* Typed Lean and numerical controls

[[file:CheckArtifact.lean][CheckArtifact.lean]] calls =Import.IR.parseProgram=, which checks graph
structure, shapes, dtypes and the interface. Given a numerical request,
it also loads exact element words through =NN.IR.Reference.load=,
loads the typed payload, and evaluates the program using TorchLean's
FloatLib-backed reference interpreter. It compares complete output
words against PyTorch's output for that example. No numerical rules
are replaced by the probe.

The first extension should connect the existing
[[https://github.com/lean-dojo/TorchLean/blob/f37cbc5aca8e79943b0ef0e3d3499ca9719d7c2b/NN/Spec/Layers/Embedding.lean][Spec.Embedding.lookup]] semantics to this import/execution path. That
specification uses =Fin vocab= indices and appends the embedding width to
the index tensor's shape. The bridge must handle PyTorch's =int64=
indices, their legal bounds, frozen weight words, heterogeneous element
types and lookup execution. The later quantization and computed-weight
gaps remain separate obligations.
